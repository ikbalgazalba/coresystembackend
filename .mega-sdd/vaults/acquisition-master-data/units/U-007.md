# Unit U-007 — Transaction-Code + Transaction-Type config (E22-E25)

## Goal

Implement `cfg_transaction_code` + `cfg_transaction_type` (E22-E25). `transaction_type_code` `[LOCKED]` external-FK char-for-char (BR-PRODASSET-7). PATCH hanya `is_active` (BR-BE07-18); `mapping` disimpan eksplisit (bukan derive `substring`). Upsert (BR-BE07-19). Maker-checker untuk TRANSACTION_TYPE (BR-BE07-05).

## Implementation steps

1. `TransactionCode.java` `@Entity @Table(name="cfg_transaction_code")` extends `VersionedEntity`. Fields BE-07 §3.3: `branchId` FK, `transactionCode` (upper-case normalized server-side BR-BE07-19), `formRequester`, `formApproval`. Key `ux_..._branch_id_transaction_code`.
2. `TransactionType.java` `@Entity @Table(name="cfg_transaction_type")` extends `VersionedEntity`. Fields: `transactionTypeCode` (`[LOCKED]` external-FK char-for-char — `@Column(name="transaction_type_code")`), `description` (immutable pasca-create), `mapping` (FK logis ke TransactionCode — **disimpan eksplisit, NOT derive `substring(0,2)`** BR-BE07-18), `isActive`. Key `ux_..._transaction_type_code`.
3. `TransactionTypeService` — E23 upsert (satu aksi Save BR-BE07-19; upper-case normalize); E25 POST (create) + PATCH (`is_active` ONLY — `422` on any other field BR-BE07-18; `mapping` must reference existing TransactionCode). TRANSACTION_TYPE write → maker-checker (U-010).
4. `TransactionTypeController` `@RestController` — E22 list per branch, E23 PUT upsert, E24 list by code, E25 POST/PATCH. Auth: Hierarchy Admin maker + checker.
5. `TransactionTypeConfigTest` — AC-11 (PATCH `description` → 422, only `is_active` accepted; `mapping` stored eksplisit tidak berubah jika kode di-rename tidak dimungkinkan); upsert upper-case; `mapping` references existing TransactionCode or `422`.

## Acceptance criteria

- `TransactionType.transactionTypeCode` `[LOCKED]` external-FK `@Column` (BR-PRODASSET-7 — char-for-char match committee routing).
- E25 PATCH hanya terima `is_active` (AC-11, BR-BE07-18); `description`/`code`/`mapping` immutable pasca-create → `422`.
- `mapping` disimpan eksplisit (NOT derived from `substring(0,2)` — BR-BE07-18; OQ-MASTERDATA-08 tidak perlu resolved bila mapping eksplisit).
- E23 upsert (satu aksi Save, upper-case server-side — BR-BE07-19).
- `mapping` must reference existing TransactionCode → `422 TRANSACTION_CODE_NOT_FOUND`.
- TRANSACTION_TYPE write → maker-checker (BR-BE07-05).
- All tests pass.
