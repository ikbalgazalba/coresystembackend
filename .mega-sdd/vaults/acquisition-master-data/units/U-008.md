## Implementation steps

1. `HierarchyMatrix.java` `@Entity @Table(name="cfg_hierarchy_matrix")` extends `VersionedEntity`. Fields BE-07 §3.3: `transactionTypeCode` FK, `level` (integer), `picNik`/`picName`, `nextPicNik`/`nextPicName` (nullable), `isApprover` (boolean), `statusApprover` (string — vestigial, evaluate retire), `escalationDays` (integer — vestigial force-set "1", konsep eskalasi `[VERIFIED][LOCKED]`), `isActive`. Key `ux_..._type_level_pic_branch` (`transaction_type_code`,`level`,`pic_nik`,`branch_id`) — paritas V1 SP legacy.
2. `HierarchyMatrixRepository extends JpaRepository` + `findByTransactionTypeCodeAndBranchId(...)`.
3. `HierarchyMatrixService` — E27 insert/update dengan validasi **server-side** (BR-BE07-15..17, fix OQ-MASTERDATA-02):
   - BR-BE07-15: `level==1 && isApprover==true` → `422 HIERARCHY_RULE_VIOLATION` (Level-1 bukan terminal approver).
   - BR-BE07-16: `isApprover==false && nextPicNik==null` → `422 NEXT_PIC_REQUIRED`; `isApprover==true && nextPicNik!=null` → `422 NEXT_PIC_MUST_BE_EMPTY`.
   - BR-BE07-17: `picNik`/`nextPicNik` WAJIB ada di `EmployeeMirror` & `!isResigned` (fix V4 NIK tanpa guard) → `422 PIC_NOT_FOUND`/`PIC_RESIGNED`.
   - (V6 kontiguitas level — cleansing import-time OQ-MIG-05; runtime: optional check `level` gap, warn not block unless policy decided).
   - APPROVAL_HIERARCHY_LEVEL write → maker-checker (U-010, BR-BE07-05).
   - E28 PIC picker: `EmployeeMirror` filtered job-title codes eligible (paritas `sp_get_pagination_data_pic_trans_type_hierarchy`).
4. `HierarchyMatrixController` `@RestController` — E26 list per type, E27 POST/PATCH (maker+checker), E28 GET pic-candidates. Auth: Hierarchy Admin.
5. `HierarchyMatrixValidationTest` — AC-10 (Level-1 is_approver → 422; next_pic required/empty; PIC resigned → 422) — all server-side, no JS dependency.
