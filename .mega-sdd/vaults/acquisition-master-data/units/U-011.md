# Unit U-011 — Lookup Tier C ACL layer + generic E30 (FC_MSTAPP_MCF read-only)

## Goal

Implement generic E30 `/lookups/{lookup_key}` (Tier C — `FC_MSTAPP_MCF` 310 master via ACL, NO local table) + `LookupAclClient` + `LookupKeyRegistry`. Filter `applicant_type` = set-membership eksplisit (fix EC5). Kegagalan baca = `503 LOOKUP_SOURCE_UNAVAILABLE` (fix EC1/EC12/fuel silent-success, BR-BE07-22). Default active-only.

## Context

- **Vault source:** `03-data-model.md §Lookup eksternal yang DISERVE read-only (Tier C)`; `04-flows.md F-U-006` (E30); `constitution §B-016` (ACL boundary — no cross-DB/linked-server pola aplikasi baru), `§I-008` (lookup fail=503); `06-constraints.md BR-BE07-12/21/22/26`
- **Binding refs:** C-13 (Tier C ACL NEW — no local table), C-18 (lookup fail=503 not sukses-kosong), OQ-EXTMASTERS-01 (ownership — Tier C stays read-only until resolved), OQ-EXTMASTERS-07 (8 objek absen dari dump — ACL handles missing as `503`)
- **Why this scope:** BE-07 §10 urutan (5) lookup layer. 01-05 semua butuh lookup (27+ applicant klasifikasi, bank, location+OJK crosswalk, product/asset). `503` not sukses-kosong = do-not-replicate (EC1/EC12/fuel). ACL boundary = BR-BE07-26 (no cross-DB three-part-name).

## Implementation steps

1. `LookupKeyRegistry.java` — registry of `lookup_key` → ACL query config (key, backing store identifier, filters supported: `applicant_type`/`parent_id`/`branch_id`/`include_inactive`). Initial keys from BE-07 §3.5 (marital-status, identity-type, economic-sector, bank, location, asset-brand, ...). Adding key = konfigurasi, not new endpoint. **Note: `branch_id` here is a query-filter parameter (lookup scope), NOT an entity FK column — no derived `branch` relation accessor needed on a lookup DTO (lookup is read-only via ACL, no local entity). Siblings U-006/U-008 declare `branch` relation on their entities (`mst_dealer_branch_access`, `cfg_hierarchy_matrix`) which DO carry `branch_id` as an entity FK; U-011 has no entity, so the relation is N/A — declared here for sibling-consistency parity.**
2. `LookupAclClient.java` — ACL adapter to `FC_MSTAPP_MCF` backing store (transport OQ-ARCH-STACK — stub interface `fetch(key, filters)`; real adapter TBD; NO cross-DB three-part-name / linked-server four-part-name — BR-BE07-26). On backing unreachable → throw `LookupSourceUnavailableException`.
3. `LookupService` — E30 `getLookup(key, filters)`: validate key in registry (else `404 LOOKUP_KEY_UNKNOWN`); `applicant_type` filter = set-membership eksplisit against many-to-many mapping (fix EC5 BR-BE07-12 — NOT substring match); default `include_inactive=false` (BR-BE07-21); hierarki (economic-sector, debtor-group, asset taxonomy) accepts `parent_id`. Map `LookupSourceUnavailableException` → `503 LOOKUP_SOURCE_UNAVAILABLE` + `correlation_id` (BR-BE07-22).
4. `LookupController` `@RestController @RequestMapping("/lookups")` — E30 GET `/{lookup_key}`. Response: `{lookup_key, source_tier:"C_EXTERNAL_READONLY", items[], page, total_pages, record_count}`. Auth: Authenticated.
5. `LookupTierCTest` — AC-12 (identity-type KITAS ter-map only P; `?applicant_type=C` → KITAS not returned; no partial-text match), AC-13 (backing unreachable → `503 LOOKUP_SOURCE_UNAVAILABLE` + correlation_id, NOT 200 empty).

## Acceptance criteria

- E30 `applicant_type` filter = set-membership eksplisit (AC-12, fix EC5 BR-BE07-12 — NOT substring match).
- E30 backing unreachable → `503 LOOKUP_SOURCE_UNAVAILABLE` + `correlation_id` (AC-13, BR-BE07-22 — NOT `200` empty list; do-not-replicate EC1/EC12/fuel).
- E30 default active-only; `include_inactive=true` for admin (BR-BE07-21).
- Response `source_tier:"C_EXTERNAL_READONLY"` (boundary transparency — BE-07 §1.3).
- NO local `mst_` table for Tier C (ACL only — BR-BE07-26).
- NO cross-DB three-part-name / linked-server four-part-name (BR-BE07-26 — ACL adapter, transport OQ-ARCH-STACK stub).
- `MsBank.PasscodeBiBca` NEVER exposed (BR-BE07-25 REDACTED-SECRET — ACL adapter must strip/exclude).
- Lookup key not in registry → `404 LOOKUP_KEY_UNKNOWN`.
- All tests pass.
