# Unit U-004 — Menu tree + role grants + menu efektif endpoint (E6/E9-E11)

## Goal

Implement `cfg_menu` (tree, `trans_type_id_prefix` `[LOCKED]`) + `cfg_menu_role_grant` (re-key position→role D-10) + `MenuController` (E6 menu efektif, E9 CRUD, E10/E11 grants). Mutasi `trans_type_id_prefix` → maker-checker (BR-BE07-14). Deactivate-only (no DELETE, BR-BE07-03).

## Context

- **Vault source:** `03-data-model.md §User management (Tier A)` (Menu, ROLE_MENU_GRANT, USER_MENU_GRANT_SPECIAL); `04-flows.md F-U-002`; `constitution §I-007` (trans_type_id_prefix external-FK LOCKED, mutasi→maker-checker), `§I-003` (no hard delete); `06-constraints.md BR-BE07-14`
- **Binding refs:** C-01 (menu NEW), C-09 (E6/E9-E11), C-16 (trans_type_id_prefix external-FK LOCKED), OQ-BE07-05 (USER_MENU_GRANT_SPECIAL retained? — build only if retained; default skip)
- **Why this scope:** BE-07 §10 urutan (2). E6 menu efektif = prasyarat app-shell FE. `trans_type_id_prefix` = input struktural komposisi `trans_type_id` (BR-PRODASSET-14) — mutasi diam-diam memutus routing approval.

## Implementation steps

1. `Menu.java` `@Entity @Table(name="cfg_menu")` extends `VersionedEntity`. Fields BE-07 §3.1: `id`, `parentId` (self-FK nullable, tree), `module`, `name`, `route`, `transTypeIdPrefix` (String(2) `[LOCKED]` verbatim — `@Column(name="trans_type_id_prefix")`), `displayOrder`, `isActive`. (kelas `cfg_` — konfigurasi navigasi/authz; lifecycle `is_active` bukan `effective_from/to`).
2. `MenuRoleGrant.java` `@Entity @Table(name="cfg_menu_role_grant")` — `role` (Role enum D-10), `menuId` FK, `isViewOnly`, `isActive`. Key `ux_cfg_menu_role_grant_role_menu_id`. Re-key position→role (OQ-BE07-05 — bukan copy 1:1; role-based).
3. `MenuRepository` — `findByParentIdIsNullAndIsActiveTrueOrderByDisplayOrder(...)`, `findByRole(Role)` join grants.
4. `MenuService` — E9 CRUD (deactivate-only, no DELETE — BR-BE07-03); mutasi `trans_type_id_prefix` → route through maker-checker envelope (U-010, TBD until U-010 lands — for now throws `UnsupportedOperationException("maker-checker envelope U-010 pending")` OR if U-010 landed, enqueue change-request + warning listing transaction-type ter-impact, BR-BE07-14). E6 menu efektif: role grants + special grants − inactive (returns tree, `trans_type_id_prefix` NOT exposed in E6 — only E9 admin).
5. `MenuController` `@RestController @RequestMapping("/menus")` E9 + `/users/{id}/menus` E6 + `/roles/{role}/menu-grants` E10. Auth: Credit (Admin); prefix change → maker+checker.
6. `MenuGrantTest` — AC-4 (menu efektif per role: only active menu + active grant returned, tree with `is_view_only`), AC-5 (prefix change → pending_approval + transaction-type ter-impact listed; routing unchanged without approve).

## Acceptance criteria

- `Menu.transTypeIdPrefix` `[LOCKED]` `VARCHAR(2)` (BR-PRODASSET-14).
- E6 returns only active menu + active grant, tree shape, `is_view_only`; `trans_type_id_prefix` NOT in E6 response (internal routing — only E9 admin).
- E9 no DELETE route (BR-BE07-03); deactivate-only via PATCH `is_active=false`.
- Mutasi `trans_type_id_prefix` → `pending_approval` (maker-checker) + warning daftar transaction-type ter-impact; tanpa approve, routing tidak berubah (AC-5, BR-BE07-14).
- `cfg_menu_role_grant` keyed by `(role, menu_id)` — role-based not position-based (OQ-BE07-05).
- `cfg_menu_user_grant_special` NOT built this unit (OQ-BE07-05 default skip — risiko backdoor D-09).
- All tests pass.
