# Unit U-006 — Dealer bank-reference + controller E12-E21 + payment-eligible-contacts

## Goal

Implement `mst_dealer_bank_reference` (payout `[LOCKED]` zero-diff, maker-checker WAJIB) + `DealerController` E12-E21. E18 bank-ref write → `202 pending_approval` (maker-checker envelope U-010). E21 payment-eligible-contacts = join job-title→personnel→bank-ref aktif simultan (BR-BE07-10). FK parent eksplisit (fix EC7).

## Context

- **Vault source:** `03-data-model.md §Dealer master family (Tier A)` (DealerBankReference); `04-flows.md F-U-004` (E12-E21); `constitution §I-002` (maker-checker WAJIB payout); `06-constraints.md BR-BE07-05/07/08/09/10`
- **Binding refs:** C-03 (bank-ref), C-10 (E12-E21 endpoints), C-14 (maker-checker envelope), OQ-BE07-01 (checker scope — TBD; envelope routes change-request, checker identity resolved at approve time)
- **Why this scope:** BE-07 §10 urutan (3). Bank-ref = payout target `[LOCKED]` — maker-checker WAJIB (BR-BE07-05). Depends on U-010 maker-checker envelope. E21 = konsumsi disbursement (STEP 16) eligibility.

## Implementation steps

1. `DealerBankReference.java` `@Entity @Table(name="mst_dealer_bank_reference")` extends `VersionedEntity`. Fields BE-07 §3.2: `dealerCode` FK, `bankReferenceId`, `accountType`, `accountDescription`, `bankId` (FK → BANK Tier C), `accountNumber`/`accountName` `[LOCKED]` payout zero-diff, `bankChargesFlag`, `status` (enum `A|inactive`), `activationDate`/`deactivationDate`. Key `ux_..._dealer_code_bank_reference_id`.
2. `DealerBankReferenceRepository extends JpaRepository`.
3. `DealerService` — E13 create (KTP/NPWP format validated `[LOCKED]` — `422` on bad format; `409 DEALER_CODE_EXISTS`; `422 PARENT_DEALER_NOT_FOUND` FK eksplisit fix EC7), E14 update (field identitas legal → maker-checker), E15 lifecycle, E16-E17 personnel/job-title CRUD, E18 bank-ref (**ALL write via maker-checker U-010** → `202 pending_approval`), E19 branch-access (replace-set atomik), E20 documents, E21 payment-eligible-contacts (join job-title→personnel→bank-ref ALL active simultan, BR-BE07-10/BR-DLRPTN-1).
4. `DealerController` `@RestController @RequestMapping("/dealers")` — E12 list (filter `branch_id` only dealer with active `DEALER_BRANCH_ACCESS` BR-BE07-07, `is_used_car`, `status`; PageResponse), E13-E21. Auth: Authenticated read / Credit (Admin) maker; E18 maker+checker.
5. `DealerControllerTest` — AC-6 (branch-scoped picker), AC-7 (PARENT_DEALER_NOT_FOUND FK eksplisit), AC-8 (E18 → 202 pending_approval; self-approve → 403 SELF_APPROVAL_BLOCKED), AC-9 (E21 eligible = all active simultan).

## Acceptance criteria

- E18 bank-ref write → `202 pending_approval` (NOT `201`); record NOT eligible payout until checker approve (AC-8).
- Self-approve change-request → `403 SELF_APPROVAL_BLOCKED` (D-01 S11).
- `accountNumber`/`accountName` `[LOCKED]` payout zero-diff `@Column` mapped.
- E21 payment-eligible-contacts: kontak hilang dari set eligible bila salah satu (job-title/personnel/bank-ref) non-aktif (AC-9, BR-BE07-10).
- E13 `422 PARENT_DEALER_NOT_FOUND` (FK eksplisit — fix EC7, NOT join via `notes`).
- E12 filter `branch_id` hanya dealer ber-akses aktif (BR-BE07-07).
- `is_sub_dealer_enabled` flag used (not name-literal — inherited from U-005).
- All tests pass.
