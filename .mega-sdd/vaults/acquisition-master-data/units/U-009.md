# Unit U-009 — Maker-checker envelope engine E37 (generic change-request)

## Goal

Implement generic maker-checker envelope E37: `log_master_change_request` + `log_master_audit` (append-only) + `MakerCheckerService` + `MasterChangeRequestController`. Resource sensitif (BR-BE07-05) write → `pending_approval`; checker (≠ maker, `403 SELF_APPROVAL_BLOCKED`) approve/reject. State machine §7.2. Maker-checker = kontrol BARU (legacy TIDAK punya — jangan klaim paritas).

## Implementation steps

1. `MasterChangeRequest.java` `@Entity @Table(name="log_master_change_request")` (append-only, INSERT-only — DB-CONVENTIONS §1 `log_`). Fields: `id`, `resource` (string — e.g. "dealer-bank-reference"), `resourceId` (nullable, for update/delete target), `action` (enum `create|update|deactivate|reactivate|delete`), `payload` (JSON — proposed mutation), `status` (enum `pending_approval|applied|rejected|cancelled`), `makerNik`, `submittedAt`, `checkerNik`, `checkedAt`, `checkerNote`, `rejectReason`. NO `updated_at` (append-only — only `created_at`/`created_by` per DB-CONVENTIONS §4 log_).
2. `MasterAudit.java` `@Entity @Table(name="log_master_audit")` — before/after JSON snapshot per Tier A mutation (BR-BE07-04). Append-only.
3. `MasterChangeRequestRepository extends JpaRepository` + `findByStatusAndResource(..., Pageable)`.
4. `MakerCheckerService` — `submit(resource, action, payload, makerNik)` → persists `pending_approval` + returns `202` envelope; `approve(changeRequestId, checkerNik, note)` → guard `checkerNik != makerNik` (`403 SELF_APPROVAL_BLOCKED` D-01 S11) + checker has role for resource (OQ-BE07-01 — role check stub until resolved) → `applied` + apply mutation (callback to resource service) + audit `log_master_audit` (before/after); idempotent by `Idempotency-Key`. `reject(changeRequestId, checkerNik, reason)` → `rejected` (reason wajib); `cancel(changeRequestId, makerNik)` → `cancelled` (only maker). Terminal `applied`/`rejected`/`cancelled` immutable.
5. `MasterChangeRequestController` `@RestController @RequestMapping("/master-change-requests")` — E37 GET list (filter status/resource, PageResponse; inbox checker), POST `/{id}/approve`, POST `/{id}/reject`. Auth: maker / checker.
6. `MakerCheckerEnvelopeTest` — AC-8 (submit → 202 pending_approval; self-approve → 403 SELF_APPROVAL_BLOCKED; approve idempotent; reject reason wajib; terminal immutable; cancel only maker).

## Acceptance criteria

- E37 submit → `202 Accepted` with `pending_approval` (NOT `201` — AC-8).
- `approve` by same NIK as maker → `403 SELF_APPROVAL_BLOCKED` (D-01 S11, AC-8).
- `approve` idempotent by `Idempotency-Key` (replay returns first result).
- `reject` requires `rejectReason`; `cancel` only by maker; nol perubahan pada master.
- Terminal `applied`/`rejected`/`cancelled` immutable (further action → `409`).
- `log_master_change_request` + `log_master_audit` = append-only INSERT-only (no `updated_at` — DB-CONVENTIONS §4 log_).
- Maker-checker = kontrol BARU (no claim of legacy parity — `12-...§3a`).
- Checker role-per-resource check = stub (OQ-BE07-01 — TODO comment, not silent).
- All tests pass.
