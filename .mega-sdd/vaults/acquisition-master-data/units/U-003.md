# Unit U-003 — APP_USER entity + role enum D-10 + user provisioning (E1-E7)

## Goal

Implement `mst_user` + `mst_user_branch_scope` + `Role` enum (D-10, NO `SUPER_USER` D-09) + `AppUserService`/`AppUserController` (E1-E5 + E7). No password field (BR-SHELL-1 LDAP). Auto-deactivate on HR resign (BR-BE07-27 listener). TIDAK ada `mst_role` table selama enum tertutup (D-MD-04).

## Context

- **Vault source:** `03-data-model.md §User management (Tier A)`; `04-flows.md F-U-001` (E1-E7); `constitution §I-004` (role enum tertutup D-10, no SUPER_USER, no mst_role), `§I-005` (no password, NIK must exist & not resigned); `06-constraints.md BR-BE07-01/02/27`
- **Binding refs:** C-01 (user/RBAC NEW), C-09 (E1-E7 endpoints), C-15 (role enum D-10 LOCKED — existing `Users.urole` Long = jwt-login distinct, NOT conflict), OQ-BE07-04 (single vs multi-branch scope), OQ-BE07-03 (HO roles expand enum — deferred)
- **Why this scope:** Prasyarat app-shell FE (menu efektif) + no-self-approval di semua modul. BE-07 §10 urutan (2) APP_USER/role/menu. `mst_user` distinct dari jwt-login `Users`/`mojf_users` (binding coexistence note).

## Implementation steps

1. `Role.java` enum `[LOCKED]` D-10: `CMO, MARKETING_HEAD, CREDIT_ANALYST, KEPALA_CABANG, CREDIT_ADMIN`. **NO `SUPER_USER`** (D-09). Persist as `VARCHAR` + `@Check` constraint (DB-CONVENTIONS §3 enum kecil). No `mst_role` table (D-MD-04).
2. `AppUser.java` `@Entity @Table(name="mst_user")` extends `VersionedEntity`. Fields BE-07 §3.1: `employeeNik` (String `ux_mst_user_employee_nik`, FK logis → `EmployeeMirror.nik`), `role` (Role enum), `companyId`, `branchScope` (`@OneToMany` → `AppUserBranchScope`), `isActive` (boolean), `deactivationReason` (enum `manual|hr_resigned`), `activationDate`, `deactivationDate`. **NO `password` field** (BR-SHELL-1), **NO `isSuperUser`** (D-09).
3. `AppUserBranchScope.java` `@Entity @Table(name="mst_user_branch_scope")` — `userId` FK, `branchId`. (single vs multi OQ-BE07-04 — list supports both; default single).
4. `AppUserRepository extends JpaRepository<AppUser, Long>` + `findByEmployeeNik(String)` + `existsByEmployeeNik(String)`.
5. `AppUserService` — E2 provision: validate `employeeNik` exists in `EmployeeMirror` & `!isResigned` (BR-BE07-02, else `422 EMPLOYEE_RESIGNED`); reject `SUPER_USER` (not in enum → `422 UNKNOWN_ROLE` D-09); unique check (`409 USER_ALREADY_EXISTS`); `@Transactional`. E5 deactivate/reactivate (reactivate rejected `409` if mirror resigned). `@EventListener` on HR resign event (from U-002 sync) → auto-deactivate `deactivationReason=hr_resigned` (BR-BE07-27).
6. `AppUserController` `@RestController @RequestMapping("/users")` — E1 list (PageResponse), E2 POST provision, E3 GET detail, E4 PATCH role/scope, E5 deactivate/reactivate, E7 GET `/roles` (static D-10 catalog). Auth: Credit (Admin). Returns DTOs (never entity — constitution §C-002).
7. `AppUserProvisioningTest` — AC-1 (happy path), AC-2 (SUPER_USER → 422), AC-3 (resigned → 422 + auto-deactivate), `409 USER_ALREADY_EXISTS`.

## Acceptance criteria

- `Role` enum = exactly D-10 values; `SUPER_USER` not present; `POST /users role=SUPER_USER` → `422 UNKNOWN_ROLE` (AC-2).
- `AppUser` has NO `password`/`isSuperUser` fields (BR-SHELL-1/D-09).
- E2 rejects NIK not in mirror (`422 EMPLOYEE_NOT_FOUND`) or resigned (`422 EMPLOYEE_RESIGNED`) — eksplisit, bukan sukses-kosong (AC-3, BR-BE07-22).
- `409 USER_ALREADY_EXISTS` on duplicate `employeeNik`.
- E5 reactivate rejected `409` if mirror `isResigned=true`.
- HR resign event → auto-deactivate (BR-BE07-27) — listener test.
- `GET /roles` returns static D-10 catalog (E7).
- `POST /employees` NOT on this controller (HR system-of-record).
- No `mst_role` table created (D-MD-04).
- All tests pass.
